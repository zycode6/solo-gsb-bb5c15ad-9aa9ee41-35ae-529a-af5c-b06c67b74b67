# 舞台走位校验系统

一款舞台走位（Blocking）校验 Web 应用：在「舞台区域连接图」上标注各区域间的通行耗时，为演员按时间下达「到位口令」，系统自动按时间顺序计算相邻口令之间的**最短通行耗时**，标出**无法按时抵达**的区段并给出**所需秒数 / 可用秒数**，支持编辑后即时重算与一键导出 Markdown 校验报告。

技术栈：Node.js + Express + 原生 HTML/CSS/JavaScript（无任何前端构建步骤）。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后访问：**http://localhost:3000**

> 首次启动时，若数据文件不存在，系统会自动写入内置示例数据（9 个舞台区域、11 条连接、3 位演员、12 条口令，含刻意设计的「超时」与「不可达」演示区段）。

## 配置项

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | Web 服务监听端口（Compose 中映射为主机 3000 端口） |
| `DATA_DIR` | `./data`（容器内 `/app/data`） | 数据文件 `data.json` 存放目录 |

Compose 默认将数据目录挂载为命名卷 `stage-data` 以持久化修改；执行 `docker compose down -v` 删除卷后重启即可恢复示例数据（也可在页面右上角点击「恢复示例数据」）。

## 本地开发（不用 Docker）

```bash
npm install
npm start
# 访问 http://localhost:3000
```

要求 Node.js ≥ 18。

## 功能说明

- **舞台区域**：维护区域名称与备注（如 舞台中央、侧台右、后台化妆间）。
- **区域连接**：维护无向连接及通行耗时（秒），同一对区域仅允许一条连接。
- **演员**：维护演员姓名与角色。
- **到位口令**：按「演员 + 目标区域 + 时间」下达口令，时间支持 `90`（秒）或 `01:30`（分:秒）两种输入格式。
- **校验结果**：对每位演员，将其口令按时间升序排列，用 Dijkstra 算法计算相邻口令两区域间的最短通行耗时：
  - ✅ **可达**：所需 ≤ 可用，显示余量秒数与最短路线；
  - ❌ **超时**：所需 > 可用，红色高亮并显示「所需 X 秒 / 可用 Y 秒、缺口 Z 秒」；
  - ⛔ **不可达**：两区域在连接图上不连通。
- **即时重算**：任何新增 / 编辑 / 删除操作保存后立即重新校验并刷新结果。
- **导出报告**：点击「导出校验报告」下载 Markdown 格式报告（含汇总表与每位演员的区段明细）。
- **级联一致性**：删除区域会同时删除相关连接与口令；删除演员会同时删除其全部口令。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/data` | 获取全部数据（区域 / 连接 / 演员 / 口令） |
| GET | `/api/validate` | 执行走位校验，返回区段级结果 |
| GET | `/api/report` | 下载 Markdown 校验报告 |
| POST | `/api/reset` | 恢复内置示例数据 |
| POST / PUT / DELETE | `/api/areas`、`/api/edges`、`/api/actors`、`/api/cues`（`/:id`） | 四类资源的增改删 |

## 项目结构

```
├── server.js            # Express 入口
├── src/
│   ├── store.js         # JSON 文件持久化 + 示例数据初始化
│   ├── graph.js         # Dijkstra 最短通行耗时
│   ├── validate.js      # 走位校验核心逻辑
│   ├── report.js        # Markdown 报告生成
│   └── routes.js        # REST API 路由与入参校验
├── public/              # 前端（原生 HTML/CSS/JS）
├── seed/sample-data.json# 内置示例数据
├── Dockerfile
└── docker-compose.yml
```
